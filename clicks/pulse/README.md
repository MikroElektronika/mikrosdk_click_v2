# Software Support

## Example Description

> This example demonstrates the use of the PULSE Click board by monitoring
the pulse signal generated by the NE555 timer on the selected pin (OUT or INT)
and logging every change of its logic state on the USB UART.

### Example Libraries

- MikroSDK.Board
- MikroSDK.Log
- Click.PULSE

### Example Key Functions

- `pulse_cfg_setup` This function initializes Click configuration structure to initial values.
```c
void pulse_cfg_setup ( pulse_cfg_t *cfg );
```

- `pulse_init` This function initializes all necessary pins and peripherals used for this Click board.
```c
err_t pulse_init ( pulse_t *ctx, pulse_cfg_t *cfg );
```

- `pulse_read_pin` This function reads the logic state of the selected pulse output pin.
```c
err_t pulse_read_pin ( pulse_t *ctx, uint8_t pin, uint8_t *state );
```

### Application Init

> Initializes the driver and logger, and reads the initial logic state of the selected pin.

```c
void application_init ( void ) 
{
    log_cfg_t log_cfg;  /**< Logger config object. */
    pulse_cfg_t pulse_cfg;  /**< Click config object. */

    /** 
     * Logger initialization.
     * Default baud rate: 115200
     * Default log level: LOG_LEVEL_DEBUG
     * @note If USB_UART_RX and USB_UART_TX 
     * are defined as HAL_PIN_NC, you will 
     * need to define them manually for log to work. 
     * See @b LOG_MAP_USB_UART macro definition for detailed explanation.
     */
    LOG_MAP_USB_UART( log_cfg );
    log_init( &logger, &log_cfg );
    log_info( &logger, " Application Init " );

    // Click initialization.
    pulse_cfg_setup( &pulse_cfg );
    PULSE_MAP_MIKROBUS( pulse_cfg, MIKROBUS_POSITION_PULSE );
    if ( DIGITAL_OUT_UNSUPPORTED_PIN == pulse_init( &pulse, &pulse_cfg ) ) 
    {
        log_error( &logger, " Communication init." );
        for ( ; ; );
    }

    /* Store the initial state of the selected pin */
    pulse_read_pin( &pulse, DEMO_PULSE_PIN, &pin_state );
    
    log_info( &logger, " Application Task " );
}
```

### Application Task

> Polls the selected pin and logs its new logic state each time the pulse signal
changes its level.

```c
void application_task ( void ) 
{
    uint8_t new_state = 0;

    if ( ( PULSE_OK == pulse_read_pin( &pulse, DEMO_PULSE_PIN, &new_state ) ) && 
         ( new_state != pin_state ) )
    {
        pin_state = new_state;
        if ( pin_state )
        {
            log_printf( &logger, " %s pin: HIGH\r\n", DEMO_PIN_NAME );
        }
        else
        {
            log_printf( &logger, " %s pin: LOW\r\n\n", DEMO_PIN_NAME );
        }
    }
}
```

### Note

> The selected pin must match the J1 jumper position on the Click board.

## Application Output

This Click board can be interfaced and monitored in two ways:
- **Application Output** - Use the "Application Output" window in Debug mode for real-time data monitoring.
Set it up properly by following [this tutorial](https://www.youtube.com/watch?v=ta5yyk1Woy4).
- **UART Terminal** - Monitor data via the UART Terminal using
a [USB to UART converter](https://www.mikroe.com/click/interface/usb?interface*=uart,uart). For detailed instructions,
check out [this tutorial](https://help.mikroe.com/necto/v2/Getting%20Started/Tools/UARTTerminalTool).
